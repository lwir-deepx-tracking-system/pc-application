# 웹 화면 조각 (`page/`)

실시간 서버가 보여 주는 웹 화면은 `page/live_page.html` **한 파일**입니다. 서버는 그 파일만 읽습니다.
한 파일 안에 모양(CSS), 뼈대(HTML), 동작(JS)이 다 들어 있어 고치기 어려워서, 그 파일을 조각으로 나눠 이 폴더에 두었습니다.

- **`live_page.html` 은 손으로 고치지 않습니다.** 이 폴더의 조각을 고치고 `build_page.py` 로 다시 만듭니다.
- 조각을 순서대로 이어 붙인 것이 곧 `live_page.html` 입니다. 이어 붙일 때 글자 하나, 줄바꿈 하나도 더하거나 빼지 않습니다.
- 서버는 이 폴더를 읽지 않습니다. 화면이 바뀌는 것은 `live_page.html` 이 바뀔 때뿐입니다.

실시간 카메라 영상의 위쪽 테두리에는 좌우, 오른쪽 테두리에는 상하 위치를 길이가 다른 회색 눈금과 호박색 삼각형으로 보여 줍니다. v27은 짐벌에 성공적으로 보낸 이동 명령의 방향과 속도, 경과 시간을 누적해 0~100%로 표시합니다. 브리지 시작 위치가 50%입니다. 낮은 속도에서 좌우 40초, 상하 14초를 전체 눈금으로 가정한 표시이며 장착 상태에서 잰 회전 한계와는 다를 수 있습니다. 실제 회전과 오차가 누적될 수 있으므로 이 숫자는 제어에 쓰지 않습니다. 녹화 재생이나 영상 전환 중, 그리고 위치 데이터가 없거나 오래됐을 때는 눈금을 숨깁니다. 실시간 카메라 영상이 돌아오고 위치 데이터가 들어오면 다시 표시합니다.

v27 브리지가 `POSITION_EST pan_percent tilt_percent`를 보냅니다. 실측 각도와 해당 축의 범위를 함께 공급하는 브리지가 있으면 `POSE pan tilt [pan_min pan_max tilt_min tilt_max]`의 값을 눈금에 우선 반영합니다. 괄호 안의 설치 한계 네 값은 선택 항목입니다. 현재 v25·v27 브리지에는 실측 각도 송신이 없습니다. 추정 표시를 쓰려면 v27 바이너리를 다시 빌드한 뒤 서버를 재시작합니다.

## 1. 고치는 순서

1. 아래 3절 목록에서 고칠 조각을 찾습니다.
2. 그 조각 파일을 고칩니다.
3. 다시 만듭니다.

   ```
   cd tracking_server/page
   python3 build_page.py
   ```

4. 확인합니다. `같습니다` 가 나와야 합니다 (끝나는 값 0).

   ```
   python3 build_page.py --check
   ```

5. 고친 조각과 다시 만든 `live_page.html` 을 **함께** 올립니다. 한쪽만 올리면 다음 사람의 확인이 `다릅니다` 로 나옵니다.

알아 둘 것:

- 윈도우에서는 `python3` 대신 `python` 입니다. 따로 설치할 것은 없습니다 (Python 3.10 과 3.13 에서 확인).
- 고치기 **전에** `--check` 를 먼저 돌려 보세요. `다릅니다` 가 나오면 누군가 `live_page.html` 을 직접 고쳤거나, 조각을 고치고 다시 만들지 않은 것입니다. 직접 고친 것이라면 그 내용을 조각으로 옮긴 뒤에 다시 만드세요. 옮기지 않고 다시 만들면 직접 고친 내용이 사라집니다. `--check` 는 처음 다른 줄이 어느 조각의 몇 번째 줄인지 알려 줍니다.
- 장치에서: 서버(`scripts/run_real_gui.sh` 로 켠 것)는 화면을 열 때마다 `live_page.html` 을 다시 읽습니다. 파일을 바꾸고 브라우저에서 새로 고치면 바뀐 화면이 나옵니다. 서버를 다시 켜지 않아도 됩니다.
- `python3 build_page.py --list` 는 조각별 크기와 전체 md5 를 보여 줍니다. 장치의 파일과 같은지 볼 때는 `md5sum live_page.html` 과 비교합니다.

`build_page.py` 가 끝나는 값:

- 0 = 됨(또는 같음)
- 1 = `--check` 에서 다름
- 2 = 조각이 없거나 비었거나 목록이 잘못됨

## 2. 폴더 구조

```
page/
├── README.md        이 문서
├── build_page.py    조각을 이어 붙여 live_page.html 을 만드는 도구 (표준 라이브러리만 씀)
├── parts.json       조각 목록. 여기 적힌 순서대로 이어 붙임
├── html/            뼈대 3개 (문서 머리, 화면 뼈대, 문서 끝)
├── css/             모양 10개
└── js/              동작 16개
```

이어 붙이는 순서: `html/1_head` → `css/01` ~ `css/10` → `html/2_body` → `js/01` ~ `js/16` → `html/3_tail`.
나누기 전 파일에 있던 순서 그대로입니다. 파일 이름 앞의 숫자가 그 순서입니다.

## 3. 어느 조각에 무엇이 있나

### 뼈대 (`html/`)

- **`html/1_head.html`** — 문서 머리: 글자 설정, 화면 폭 설정, 제목. `<style>` 로 끝납니다.
- **`html/2_body.html`** — 화면에 보이는 뼈대 전부.
  - 위에서부터 맨 위 줄(제목, 상태 점) → 영상과 그래프 상자 (영상 바로 아래에 재생 위치 막대와 정답과 비교 숫자 줄, 재생 중·재생이 끝난 뒤에만 보임) → 상태 칸 → Filter 값 → 짐벌 제어기 → 설정 → System → 녹화 재생 → 측정 → 단축키.
  - 처음부터 화면에 적혀 있는 안내·설명 글(Filter 설명, 검출 모델 설명, 위치 기억 · 신뢰도 설명, System 설명, 녹화 재생 설명)도 여기 있습니다.
  - `</style>` 로 시작하고 `<script>` 로 끝납니다.
- **`html/3_tail.html`** — 문서 끝: `</script>` 와 닫는 표시.

### 모양 (`css/`)

각 조각이 맡는 화면의 자리입니다.

- **`css/01_base.css`** — 바탕: 색 이름표(어두운 회색 + 주황), 글꼴, 글자 선택 막기, 숫자 글꼴
- **`css/02_top_bar.css`** — 맨 위 줄: 제목, 상태 점(연결 · 짐벌 · 모델 · 측정), 깜빡임
- **`css/03_layout.css`** — 큰 배치: 왼쪽 영상 칸 (영상 아래 막대가 있으면 그만큼 영상 폭을 줄임: `--rbh`), 오른쪽 패널
- **`css/04_status.css`** — 상태 칸: 지금 상태 글자, 가로 · 세로 오차, 놓친 시간
- **`css/05_pad.css`** — 방향 버튼 · 정지 키 모양. 이 버튼들은 지금 화면에 없고 모양 규칙만 남아 있습니다
- **`css/06_sections.css`** — 오른쪽 패널의 접는 구역 안쪽: 버튼, 입력칸, 측정 결과 표, 접는 설명, 지난 측정 목록, 단축키 글자. 끝에 영상 아래 재생 막대와 정답과 비교 숫자 줄(칸이 줄바꿈되는 칩, 표 아님) 모양
- **`css/07_perf_graph.css`** — 영상 왼쪽 위 속도 · 지연 그래프 상자
- **`css/08_phone.css`** — 휴대폰 화면: 세로일 때와 가로일 때의 배치
- **`css/09_settings_tree.css`** — 설정 구역: 줄, 칸, 선택됨 · 잠김 표시, 모델 폴더 상자
- **`css/10_joystick.css`** — 휴대폰에서 영상을 끌 때 나오는 원(조이스틱), 정지 키 크기 (정지 키도 지금 화면에 없음)

### 동작 (`js/`)

각 항목: 조각 — 화면에서 하는 일. 그 아래 "이름"은 조각 안에 있는 이름입니다.

- **`js/01_helpers.js`** — 공통 도우미, 접는 구역의 열림 · 닫힘을 브라우저에 기억
  - 이름: `$`, `chip()`, `v`(영상), `S`(상태 글자), `MOB`, `openSaved`
- **`js/02_connection_status.js`** — 맨 위 연결 점, 끊긴 영상 다시 열기, 상태 글자("따라가는 중", "놓침", "대기 중")
  - 이름: `netChip()`, `openStream()`, `show()`, `ANS`
- **`js/03_gimbal_control.js`** — 짐벌 조작: 명령 보내기, 영상 누르기(사람 고르기 · 멈춤), 키보드(방향키 · W A S D · Space), 손을 떼거나 화면이 가려지면 정지, 휴대폰 끌기. 지금 화면에 없는 방향 버튼용 코드도 남아 있습니다
  - 이름: `post()`, `K`(키 → 방향), `release()`, `JOY`, `joyDir()`, `joyEnd()`
- **`js/04_ping_fps_aim.js`** — 주기적으로 서버에 묻기: 0.4초마다 상태 받기, 화면이 다시 켜지면 영상 다시 열기, fps 숫자, 가로 · 세로 오차
  - 이름: `ping()`, `wake()`, `hztick()`, `etick()`
- **`js/05_measure.js`** — 측정: 시작 · 끝 버튼, 진행 글자, 결과 표, 이름 · 메모 고치기, 지난 측정 목록
  - 이름: `table()`, `render()`, `history()`, `mshow()`, `tick()`, `mpost()`, `LEGEND`, `esc`, `f1`
- **`js/06_settings_state.js`** — 설정 · Filter 값 · System 구역의 요소 잡기, 함께 쓰는 변수, 숫자 칸을 치는 동안 덮어쓰지 않기
  - 이름: `MIN` ~ `RD`(요소), `rlast`, `mlast`, `rdirty`, `OTT`
- **`js/07_tracker_texts.js`** — "Tracker 설명"에 나오는 글 (추적기별 설명)
  - 이름: `TDC`, `BT`, `TD`
- **`js/08_tree_names_folders.js`** — 설정 칸에 보이는 이름과 한 줄 설명, 모델을 폴더(구조 → 크기)로 묶는 규칙, Tracker 설명 그리기
  - 이름: `TN`, `PN`, `DN`, `AN`, `DNOTE`, `dfold`, `dsub`, `AFOLD`, `PFOLD`, `tname`, `pend`, `rdoc()`
- **`js/09_tree_rows.js`** — 설정 줄 만들기: 전처리 · 검출 모델 · Tracker · 외형 비교 · 위치 기억 · 신뢰도 · KeepID · 제어 줄에 어떤 칸이 있고, 누르면 무엇을 보내고, 언제 잠기는지
  - 이름: `tiers()`
- **`js/10_tree_draw_click.js`** — 설정 줄 그리기(폴더 펼치기 포함), "지금 조합" 줄, 칸을 눌렀을 때 서버로 보내기
  - 이름: `otdraw()`
- **`js/11_model_change.js`** — 검출 모델 바꾸기 상태: 맨 위 모델 점, "지금 적용된 값" 첫 줄, 1초마다 다시 읽기
  - 이름: `mdl()`, `mtick()`
- **`js/12_rules_filter_values.js`** — 서버 설정을 읽어 보여 주기("지금 적용된 값"의 Filter · Tracker 줄), Filter 값 Apply 버튼
  - 이름: `rshow()`, `rtick()`
- **`js/13_system_buttons.js`** — System 구역: 카메라 초기화, 재부팅 버튼
  - 이름: `syspost()`, `CR`, `SR`
- **`js/14_start_timers.js`** — 설정과 측정을 1초마다 다시 읽기 시작
  - 이름: (`rtick`, `tick` 을 부름)
- **`js/15_perf_graph.js`** — 속도 · 지연 그래프: 켜기 · 끄기, 시간 범위, 1초마다 값 받기, 그리기
  - 이름: `PF`, `PFC`, `pfdraw()`, `pftick()`, `pfsave`
- **`js/16_replay.js`** — 녹화 재생 (2026-11-12): 녹화 목록 고르기, 초당 장 수 · 반복, 재생 시작 · 멈춤, 상태 글자, 8비트 주의. 재생 중이면 0.5초마다, 아니면 구역이 열려 있을 때만 `/replay` 를 읽습니다. 영상 아래 재생 막대(11-12 later): 재생 · 일시정지, −10초 · +10초, 위치 막대(놓을 때 `POST /replay/seek`), 장 번호로 이동, 초당 장 수 바꾸기(`/replay/speed`); 같은 `/replay` 의 `eval` 로 영상 아래 숫자 줄(오검출 크게, 옛 채점 작게, 끝난 뒤 "재생 끝, 최종"으로 남김, 닫기). 옆 패널과 영상 아래는 같은 데이터에서 그립니다. 정답과 비교(11-12): 새 채점 · 옛 채점 숫자 표, 숫자 처음부터(`POST /replay/eval/reset`), 정답 상자 그리기(`POST /replay/eval/draw`)
  - 이름: `rpShow()`, `rptick()`, `rppost()`, `rpNote()`, `RPSEC` ~ `RPMSG`(요소)

### 자주 고치는 것

각 항목: 바꾸고 싶은 것 — 볼 조각.

- **화면에 적힌 안내 · 설명 글** — 대부분 `html/2_body.html`
- **상태 글자("따라가는 중" 등)** — `js/02_connection_status.js`
- **색** — `css/01_base.css` 맨 위의 색 이름표
- **휴대폰에서의 배치** — `css/08_phone.css`
- **키보드 키, 끌기 조작** — `js/03_gimbal_control.js`
- **설정 줄에 칸을 더하거나 잠그는 조건** — `js/09_tree_rows.js`
- **설정 칸에 보이는 모델 이름, 폴더로 묶는 규칙** — `js/08_tree_names_folders.js`
- **Tracker 설명 글** — `js/07_tracker_texts.js`
- **측정 결과 표** — `js/05_measure.js`, 모양은 `css/06_sections.css`
- **그래프** — `js/15_perf_graph.js`, 모양은 `css/07_perf_graph.css`
- **짐벌 제어기 구역의 숫자(Kp 등)** — 화면에 적어 두지 않습니다.
  - 서버가 시작할 때 짐벌 프로그램에 넘긴 값을 `/rules` 의 `gimbal_cfg` 로 받아 `js/12_rules_filter_values.js` 의 `gshow` 가 그립니다.
  - 값을 바꾸려면 `scripts/live.env` (거기 없는 값은 `scripts/run_real_gui.sh`) 를 고치고 서버를 다시 시작합니다.

## 4. 지켜야 할 것

- **조각에 적은 것은 전부 그대로 화면 파일에 들어갑니다.** 조각 맨 위에 "이 파일은 …" 같은 머리말을 붙이면 그것도 들어갑니다. HTML 조각에서는 화면에 글자로 보일 수 있습니다.
- **순서를 바꾸지 않습니다.**
  - JS 조각은 모두 하나의 `<script>` 안에 순서대로 들어갑니다. 조각끼리 변수와 함수를 같이 씁니다 (예: `js/05_measure.js` 의 `esc` 를 설정 조각들도 씁니다). `const` · `let` 으로 만든 것은 그 줄이 실행된 뒤에만 쓸 수 있으므로 순서가 바뀌면 화면이 멈출 수 있습니다.
  - CSS 조각은 뒤에 나온 규칙이 앞의 규칙을 덮습니다 (예: `css/08_phone.css`, `css/10_joystick.css` 가 앞 조각의 규칙을 덮음).
- **조각의 맨 앞과 맨 끝은 그대로 둡니다.**
  - `css/01_base.css` 와 `js/01_helpers.js` 는 첫 줄이 빈 줄입니다. `<style>`, `<script>` 바로 뒤의 줄바꿈입니다.
  - `html/1_head.html` 은 `<style>` 로, `html/2_body.html` 은 `<script>` 로 끝나고 그 뒤에 줄바꿈이 없습니다. 저장할 때 끝에 줄바꿈을 자동으로 넣는 편집기를 쓰면 이 두 파일 끝에 줄바꿈이 하나 더 생깁니다. 화면은 그대로 동작하지만 화면 파일에 빈 줄이 하나 늘어납니다.
  - 그 밖의 조각은 모두 줄바꿈으로 끝납니다. 끝의 줄바꿈을 지우면 다음 조각의 첫 줄이 같은 줄에 붙습니다. 앞 조각이 `//` 주석으로 끝나면 다음 조각의 첫 줄이 주석이 되어 화면이 멈출 수 있습니다.
